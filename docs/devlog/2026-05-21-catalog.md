# Catalog expansion — 2026-05-21

Push 4. Now that the Shareable CAD pipeline is alive, the catalog has been thin (mostly geometric primitives). Adding subculture-specific designs and making the latch stubs real.

## What landed

**Six new studs** (filed under the existing contract — `module stud_<name>(size, tip_radius, height)`, origin at base center, +Z axis):

- **Industrial set** — `rivet` (mushroom-cap button), `hex_bolt` (cylinder with `$fn=6`, optional chamfer), `washer` (flat ring, negative-space)
- **Festival / symbolic set** — `star` (5-point polygon, `tip_radius` rounds the tips), `heart` (two circles + a triangle, kawaii option), `lightning` (zigzag polygon, cyberpunk)

Each file has a development render at the bottom (`stud_<name>(size = 8);`) so you can open it standalone in OpenSCAD with F5.

**Three latches converted from stubs to working geometry**:

- **`snap`** — peg-and-socket: both ends carry a flat tab that extends past the band edge; left tab has a flared peg pointing up, right tab has a matching socket on its underside. No added hardware.
- **`loop_post`** — left end has a T-headed post rising from the band's top surface; right end has a loop-frame extending past the band. Slip loop over post; T-head captures.
- **`magnetic`** — small puck on each band end with a pocket for a 6 mm × 2 mm neodymium disc magnet. Print, drop magnets in, cyanoacrylate. Polarity is the user's responsibility.

**Dispatch fix**: the previous `place_latch()` in `bracelet.scad` mirrored the right-end invocation, which placed the buckle tongue INSIDE the band rather than extending past it (visible in Push 3's first auto-render — the right end looked truncated). Replaced with a clean translate-only convention: each latch defines its left half extending -X and right half extending +X, the dispatch translates the right call to `band_length` without mirroring. The new latches were written to this convention from the start.

**`params.py`**: extended `STUD_HEIGHT_MULTIPLIERS` with the 6 new entries; added `MAGNET_DIAMETER`, `MAGNET_THICKNESS`, `MAGNET_TOLERANCE`, `MAGNET_PUCK_HEIGHT`. The drift test will catch any divergence between these and what the latch SCAD files use.

## What got free

- `tests/test_signatures.py` is parametrized over `_scad_files()` — the 6 new studs and 3 converted latches automatically gain signature tests. Test count went from 24 to 30 with no test edits.
- `docs/explainers/studs.md` automatically picks up the new entries on the next `uv run explainers build`. CI will regenerate it on push.
- `bracelet.scad`'s dispatch-completeness tests would have caught it if I'd added a new stud file under `studs/` and forgotten the `place_stud()` branch. (Didn't trigger because I remembered the branches, but the safety net is there.)
